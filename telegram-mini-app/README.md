# Торговый кабинет — Telegram Mini App

Мобильный кабинет RF-контура (профиль C3b на фьючерсах MOEX через Т-Инвестиции): капитал бота,
P&L, открытые позиции, кривая доходности, журнал закрытых сделок и винрейт — в Telegram, без
открытия дашборда.

Данные читаются **напрямую из боевого состояния** `data/live_rf/*`, которое пишет
`tools/live_rf_engine.ps1`. Приложение только читает: единственный писатель — движок.

Интерфейс — биржевой терминал: командная строка со статусом контура, тикерная лента открытых
позиций, итог дня с клавишами `F1 ДЕНЬ / F2 СДЕЛКИ / F3 ВСЁ ВРЕМЯ`, свечной график выбранной
позиции с уровнями входа, стопа и цели, плотные таблицы позиций и закрытых сделок.
Свечи — часовые, из `data/live_rf/candles/<АКТИВ>_1h.json` (их печёт `tools/bake_rf_candles.ps1`),
последние 120 баров на позицию.

## Главное про бота: этот сервер НЕ поллит Telegram

Боевого бота уже слушает `assistant/bot.py` (`trading-assistant.service` на VPS). Два процесса
с `getUpdates` на одном токене несовместимы — Telegram отдаёт 409 и ассистент падает
(это прямым текстом написано в `assistant/tg.py`). Поэтому здесь:

- Express отдаёт только API и статику, `bot.launch()` нет и не должно появиться;
- нижнюю кнопку ставит `scripts/set-menu-button.js` — одноразовый вызов `setChatMenuButton`,
  при живом polling он безопасен, ровно как `sendMessage` из торговых тиков;
- кнопка «Открыть приложение» в `/start` живёт в самом ассистенте (`assistant/bot.py`),
  включается переменной `MINI_APP_URL` в его окружении.

## Запуск

Нужен Node.js 20.19+ (или 22.12+) и публичный HTTPS для Telegram.

```bash
cd telegram-mini-app
copy .env.example .env
npm install
```

Заполнить в `.env`:

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен существующего бота — для проверки подписи `initData` и menu-кнопки |
| `WEB_APP_URL` | публичный `https://` адрес приложения (туннель или домен) |
| `ALLOWED_TELEGRAM_IDS` | **обязательно**: свой telegram id. Пусто = кабинет откроется любому |
| `RF_DATA_DIR` | путь к состоянию контура, по умолчанию `../data/live_rf` |

### Локально

```bash
npm run dev     # Vite на :5173, API на :3000, /api проксируется
```

Либо одной кнопкой — `start-local.cmd`: собирает и поднимает всё на
[http://localhost:3030](http://localhost:3030) с `DEV_ALLOW_UNSAFE_AUTH=true`. В этом режиме
API принимает запрос без `initData` — только для просмотра вёрстки в обычном браузере.

Данные берутся из локального рабочего дерева, поэтому перед просмотром — `git pull`
(облачный бот и VPS коммитят состояние каждые ~15 минут).

### Прод

```bash
npm run build
npm start       # Express отдаёт dist/ и API на PORT
```

`DEV_ALLOW_UNSAFE_AUTH` должен быть `false`: тогда API принимает только подписанный `initData`.

## Кнопки Telegram

Когда публичный HTTPS-адрес поднят и записан в `WEB_APP_URL`:

```bash
npm run set-menu-button
```

Ставит постоянную нижнюю кнопку «Открыть приложение». Выполняется один раз (и повторно — при
смене URL туннеля).

Для кнопки в `/start` — задать `MINI_APP_URL` в окружении ассистента на VPS и перезапустить
`trading-assistant`. Без этой переменной ассистент отвечает на `/start` как раньше.

## Портфели и роли

Терминал ведёт несколько портфелей. Кто что видит, задаёт `portfolios.json` рядом с `.env`
(файл в `.gitignore`, образец — `portfolios.example.json`):

```json
{
  "admins": ["<ваш telegram id>"],
  "portfolios": [
    { "id": "rf", "label": "Фьючерсы MOEX", "kind": "rf",
      "dataDir": "../data/live_rf", "currency": "RUB", "owners": [] },
    { "id": "crypto", "label": "Крипта Bybit", "kind": "crypto",
      "dataDir": "../data/live_real", "candlesDir": "../data", "currency": "USD",
      "owners": ["<telegram id владельца>"] }
  ]
}
```

- **admins** видят все портфели: при входе открывается сводка, тап по строке — терминал портфеля.
- **owners** видят только свой: сводки нет, терминал открывается сразу, клавиши возврата нет.
  Названия и само существование чужих портфелей владельцу не показываются.
- Кого нет ни там, ни там — получает 403 на любой запрос.

Решение принимает `server/portfolios.js` и **только** по telegram id из проверенной подписи.
Параметр `?portfolio=` — лишь пожелание: для чужого и для несуществующего id ответ одинаковый
(403), чтобы по разнице ответов нельзя было выяснить состав системы. Отказы пишутся в `access_log`.

Чужой счёт в будущем добавляется одной записью в `portfolios`: свой `dataDir` и свой `owners`.
Данные читает адаптер по полю `kind`: `rf` — `server/rf-data.js`, `crypto` — `server/crypto-data.js`.
Оба возвращают одну и ту же структуру, поэтому терминал в интерфейсе один.

## Доступ

`initData` подписан ботом, и проверка подписи (HMAC-SHA-256, `server/telegram-auth.js`)
доказывает, что запрос пришёл из Telegram, — но не что пришёл владелец счёта. Кабинет показывает
реальные деньги, поэтому доступ отдельно ограничен списком `ALLOWED_TELEGRAM_IDS`; отказы
пишутся в таблицу `access_log`.

SQLite (`data/mini-app.sqlite`) хранит **только** пользователей и журнал доступа. Торговых
данных в ней нет и быть не должно — источник правды один, файлы движка.

## Как считаются цифры

Ловушки этих данных собраны в `server/rf-data.js`, там же комментарии со ссылками на движок:

- **капитал** — `go.bot_capital_rub`, реальный и сверенный с брокером, а не блендовый `profile_eq`;
- **за сегодня** — от `day_start_eq`; если штамп дня отстал (движок ставит его первым тиком
  торгового дня, а ЕТС стартует в 06:00 MSK), базой берётся закрытие предыдущего дня;
- **за всё время** — `profile_eq / base_rub − 1`, то есть **доходность стратегии без пополнений**.
  Рост `bot_capital` для этого не годится: 12.08.2026 серия прыгнула +23,9% за один снимок —
  это занос денег, а не прибыль;
- **кривая** — по `profile_eq`, в одной шкале с «за всё время»; ряд прорежен до ~300 точек;
- точки эквити с `account_liquid <= 0` отбрасываются: при пустом ответе T-Invest `bot_capital`
  схлопывается в мусор и рисует фантомную просадку ~97%.

Не передавайте `BOT_TOKEN` во фронтенд и не доверяйте `initDataUnsafe`: решение о доступе
всегда принимает backend.
